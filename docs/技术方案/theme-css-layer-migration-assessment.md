# 主题 CSS Layer 化迁移评估

> 2026-07-29 · 由 v0.3.2 假分屏缺陷(`5a93c0b`)引出的架构评估。结论:值得做,但本质是"两套工具类体系的对账",不是 CSS 机制微调。

## 背景

v0.3.2 修复的假分屏根因:15 套主题 CSS 经 `main.tsx` 直接 import,不属于任何 `@layer`;按 CSS Cascade Layers 规范,无层样式优先级高于所有分层样式,故主题规则静默压过了 Tailwind v4 编译进 `@layer utilities` 的 `.hidden`。当时判断"任何工具类都可能被主题静默覆盖",建议单独评估根治方案。本文档是该评估的结果。

## 关键发现:无层覆盖是载重结构

主题压过工具类**有一部分是故意的,且正在支撑设计系统**:

1. 应用根字号为 13px(`styles.css` 的 `--font-size-base`),非浏览器默认 16px。Tailwind 所有 rem 基准工具类实际渲染为名义值的 81.25%:`gap-2` 名义 8px,实渲染 6.5px。
2. 15 套主题的 `base.css` 各定义一组与 Tailwind 同名的**影子工具类**——`.gap-1`~`.gap-4`、`.flex-1`、`.truncate`——把间距钉回 8px 网格(`gap: var(--space-2)`,15 套主题 token 值经核对完全一致:4/8/12/16px)。
3. 主题版 `.flex-1` 为 `flex:1; min-width:0; min-height:0`,比 Tailwind 版多出滚动容器收缩所需的 min 尺寸清零。

**推论:naive 的 layer 化(主题置于 utilities 之下)会让 300+ 处渲染当场翻转**——`gap-*` 裸用 200+ 处、`flex-1` 约 100 处。假分屏的镜像会全应用反向爆发。

## 现状暴露面(截至 v0.3.2)

- 全项目现存 `hidden` 工具类用法 3 处(`WorkflowEditor.tsx` 的 `lg:` 响应式),无主题规则对其元素设置 display,**无活性 bug**。
- 条件切换 display 类工具类的写法仅 1 处(`App.tsx:38`),安全。
- spec 护栏已于 `484013e` 落入 `.trellis/spec/frontend/quality-guidelines.md`。

## 规模数据

| 项 | 数据 |
|---|---|
| 主题 CSS | 149 文件 / 约 58,000 行,全部无层 |
| classic 主题 | 混在 9,335 行的 `styles.css` 内,按 `[data-ui-theme="classic"]` 前缀可抓取 |
| 影子工具类 | 6 类 × 15 套 ≈ 91 条规则,跨主题同值 |
| 原始冲突扫描 | 248 个组合 / 1,174 处命中(含大量复合选择器误报,如 `.wf-group-block > .flex` 属结构选择而非重定义) |
| 估计真实裁决点 | 几十处(元素级同时命中主题规则与工具类且属性重叠,如 `.term-window` 的 padding vs TSX 上的 `p-0`——今天主题赢,layer 化后反转) |
| 视觉回归矩阵 | 16 主题 × 8 页面 × 明暗 ≈ 256 面 |

## 建议方案:外科式拆分,三阶段 + 一个可选项

### 阶段 1:剥离影子工具类(零视觉变化)

91 条影子规则跨主题同值,合并为一份公共文件,置于**高于** utilities 的 layer(如 `@layer theme-utils`)。间距与 `flex-1` 行为原样保留。完成后各主题 `base.css` 删除同名段。

### 阶段 2:主体 layer 化 + 冲突审计

- `layer()` 仅支持 CSS `@import` 语法,故需把 `main.tsx` 中 15 个 JS import 移入 `styles.css`,改写为 `@import "./styles/x-index.css" layer(ui-themes);`,并在 Tailwind import 前声明总排序(`ui-themes` 低于 `utilities`)。
- classic 主题规则按前缀包进同一 layer。
- 跑冲突审计清单(过滤复合选择器后的元素级重叠),逐处裁决保留哪侧。

### 阶段 3:一次完整视觉回归

256 面配清单扫一遍。这是最大成本项,属 UI 设计师(han)的时间。

### 可选阶段 4(独立决策,不作为前置)

将 Tailwind `--spacing` 基准改为 4px,使 `p-*`/`m-*`/`w-*`/`h-*` 也回归 8px 网格。注意:这会全应用改变尺寸渲染(如 `w-80` 从 260px 变为名义 320px),属设计保真度修正,视觉判断权在 han,须单独拍板并伴随独立回归。

## 成本估算

- 代码与审计:1–2 天。
- 视觉回归:约 256 面,设计师按清单扫描,数小时至一天。
- 最佳时机:紧跟发版之后(评估时点 v0.3.2 刚发布,缓冲期完整)。

## 不做的代价与替代护栏

现存暴露面仅 3 处且无活性风险。若暂不迁移:

- 已有 spec 禁止模式(内联样式做状态可见性、终态不回写)。
- 可再加近零成本 CI 检查:禁止主题 CSS 新增 Tailwind 同名类;禁止 TSX 中条件切换 display 类工具类。
- 代价:隐患封存但不消除,新页面/新主题仍可能踩同类坑,且 13px 根字号与 8px 网格的漂移(`p-2` 实渲染 6.5px)长期存在。

## 附:验证方法备忘

- layer 归属验证:对构建产物 `dist/assets/index-*.css` 做括号平衡扫描,确认目标规则的 layer 栈。
- 冲突扫描脚本思路:主题 CSS 抽取「类名 → 属性集」,TSX 抽取 className 中共存的主题类与工具类,按属性别名表求交;复合选择器(`.a > .flex`)需过滤,属结构选择而非重定义。
